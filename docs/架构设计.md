# 架构设计

> 本文档说明 FA 智能诊断系统的整体架构、技术选型、端到端数据闭环与容器编排。
> 对应项目设计书第三章、第四章与第七章。

## 1. 五层解耦模型

系统自顶向下分为五层，层间通过明确定义的接口通信，互不耦合，便于单独迭代与替换：

| 层 | 技术选型 | 职责 |
|----|----------|------|
| 用户层 | Windows 浏览器 | 运维交互入口 |
| 前端展示层 | React + Tailwind + Nginx | 双栏布局：日志输入区 / 报告渲染区；打字机流式渲染；插槽号红色加粗 |
| 中间中转层 | FastAPI | 安全隔离、日志二次脱敏、Dify 代理（隐藏 API Key）、后处理格式校验 |
| AI 推理后端层 | Dify 工作流引擎 | 节点1 预处理（正则降噪+特征提取+阈值定级）→ 节点2 RAG 检索 → 节点3 LLM 推理（T=0.1，SSE 流式） |
| 边缘采集层 | Python Agent | 仅此一种采集模式；部署在被管服务器，5 分钟轮询采集硬件日志 |

## 2. 技术选型说明

| 组件 | 选型 | 备选 | 选型理由 |
|------|------|------|----------|
| 工作流引擎 | Dify 1.15.0 | LangChain / 直接调 API | 可视化编排，内置 RAG + Weaviate，SSE 流式原生支持 |
| 大模型 | DeepSeek / GLM-4 / Qwen-2.5（在线）或 Qwen2-7B + nomic-embed-text（Ollama 本地） | — | 在线 API 快速跑通，后续可切本地 Ollama 满足内网要求 |
| 向量库 | Weaviate（Dify 内置） | Chroma / Milvus | 零额外部署，Dify Compose 自带 |
| 后端框架 | FastAPI | Flask / Django | 原生异步，WebSocket 内置，适合流式 |
| 前端 | React + Vite + Tailwind | Vue / 纯 HTML | 生态成熟，组件化效率高 |
| 数据库 | SQLite（WAL） | PostgreSQL | 单机零配置，WAL 满足 MVP 并发 |
| 采集 Agent | Python 3.6+ | — | 无重型依赖，systemd 托管 |

## 3. 端到端数据闭环

```
[Agent 自动推送] 或 [运维手动粘贴]
        │
        ▼
┌──────────────────────────────┐
│  中间中转层 (FastAPI)          │
│   → 二次脱敏（入库前 + 转发前） │
│   → SQLite 落盘                │
│   → 携带隐藏 API Key 代理 Dify │
└──────────────┬───────────────┘
                │  POST /v1/workflows/run (SSE)
                ▼
┌──────────────────────────────┐
│  [节点1] Python 预处理         │  通用正则降噪 → 特征 JSON
│          + 阈值定级            │  解析失败标记 unknown_raw 全量转发
├──────────────────────────────┤
│  [节点2] RAG 知识库检索        │  向量+关键词混合 → Top-3（Score≥0.5）
├──────────────────────────────┤
│  [节点3] LLM 推理 (T=0.1)     │  四段式 Markdown 报告（流式 SSE）
│          未匹配 → 兜底文案      │
└──────────────┬───────────────┘
                │  text/event-stream
                ▼
┌──────────────────────────────┐
│  中间中转层 (FastAPI)          │
│   → ★后处理格式校验（防幻觉硬拦截）│
│   → WebSocket 向前端推送        │
└──────────────┬───────────────┘
                ▼
┌──────────────────────────────┐
│  前端渲染层                    │  物理插槽红色加粗放大
│                              │  打字机流式加载 → 归档重置
└──────────────────────────────┘
```

## 4. 容器编排

中心端以 Docker Compose 编排，服务名前缀 `fa-`（公网版）或与 Dify 共用网络（内网版）。核心服务：

| 服务 | 镜像 | 端口 | 说明 |
|------|------|------|------|
| fa-frontend | 自定义 React+Nginx | 3000 | FA 前端 |
| fa-backend | 自定义 FastAPI | 8000 | 中转层 |
| dify-api / dify-web | langgenius/dify-* | 5001 / 80 | Dify 引擎 |
| weaviate | semitechnologies/weaviate | 8080 | 向量库 |
| postgres | postgres:15 | 5432 | Dify 元数据 |
| redis | redis:6/7 | 6379 | 缓存/队列 |
| plugin-daemon | langgenius/plugin-daemon | 5002 | Dify 1.15+ 插件守护 |
| ollama | ollama/ollama | 11434 | 本地大模型（仅内网版） |
| dify-sandbox / ssrf-proxy | — | 8194 / 3128 | 代码执行与 SSRF 代理 |

> 内网离线版额外内置 Docker Engine 离线安装包，使无外网服务器也能一键拉起全部容器。

## 5. 网络与暴露面

- **3000**（TCP）：FA 前端 + API 转发，生产环境建议公网放行
- **80**（TCP）：Dify 控制台，公网放行（建议配合强密码）
- **11434**（TCP）：Ollama 推理接口，仅内网通信，外网建议关闭
- **8000**（TCP）：FastAPI 后端直连（可选，3000 已代理）
- 被管服务器 → 中心：仅需放行 **3000** 即可（Agent 从 3000 下载脚本、向 3000 推送数据）
- API 密钥经环境变量注入，不落地明文；接口仅向内网管理网开放

## 6. 容错与可靠性

- **后端调 Dify 超时提升至 2000s**：本地 Qwen2-7B CPU 推理约 5~10 tok/s，避免被 PluginDaemon 超时杀死。
- **PluginDaemon 超时 2000s**：`PLUGIN_MAX_EXECUTION_TIMEOUT` 与插件内 HTTP timeout 同步调整。
- **内存不足自动 swap**：部署脚本在内存 < 8 GB 时自动创建 8 GB swap，满足 Qwen2-7B 约 6.3 GiB 需求。
- **空数据心跳**：采集 Agent 在无硬件日志时仍发送心跳，虚拟机/云主机也能显示「在线」。

详见 [离线部署手册](离线部署手册.md) 第八章「已修复的坑」。
