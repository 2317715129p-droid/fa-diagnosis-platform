## 1. 摘要

FA 智能诊断系统（Failure Analysis Intelligent Diagnosis System）是一套面向 x86 Linux 服务器的**硬件故障智能诊断系统**。它以大语言模型（LLM）为推理引擎，以 RAG 知识库为事实锚点，以代码层后处理为防幻觉兜底，将异构硬件日志（dmesg / mcelog / IPMI SEL）自动转化为**结构化、插槽级精确定位**的失效分析（FA）诊断报告，单次诊断 5~15 秒，将故障分析由人工小时级缩短至分钟级。

系统的核心突破是提出并落地**「参数层 + 提示层 + 代码层」三重防幻觉架构**，在知识库无匹配时强制输出「无法定位，需人工硬件检测」，从机制上杜绝 AI 编造，使大模型诊断从「演示可用」达到「生产可信」，满足电信级运维对可靠性的严苛要求。

---

## 2. 项目背景与痛点

数据中心服务器硬件故障是业务中断的主要原因之一。传统运维面临三大痛点：

1. **日志异构难解析**：Dell、HPE、华为等厂商 BMC 日志格式差异巨大，人工分析耗时且易出错。
2. **知识依赖个人经验**：资深工程师排障知识难以沉淀，新人上手周期长。
3. **AI 幻觉风险**：通用大模型面对专业硬件错误码时易编造不存在的故障原因，无法直接用于生产运维。

本项目目标：极简私有化部署（一条命令、零外网依赖）、分钟级流式诊断、插槽级精确定位、工业级防幻觉。

---

## 3. 总体架构

系统采用**五层解耦模型**（详见 [架构设计](架构设计.md)）：

```
用户层 → 前端展示层(React+Nginx) → 中间中转层(FastAPI)
       → AI 推理后端层(Dify 工作流) → 边缘采集层(Python Agent)
```

端到端数据闭环：日志输入（手动/Agent）→ FastAPI 二次脱敏 + 落盘 → 代理调用 Dify 工作流（预处理 → RAG → LLM 流式推理）→ 完整报告后处理校验 → WebSocket 推送前端 → 打字机渲染 + 归档。

## 4. 核心功能设计

### 4.1 日志输入（双模式）

- **手动粘贴**：运维在前端文本框粘贴原始日志，点击「启动 AI 诊断」。
- **Agent 自动采集**：每台被管服务器部署轻量 Python 脚本，systemd 托管，每 5 分钟执行 `dmesg | grep Hardware Error`、`ipmitool sel elist`、`ipmitool sdr type ...`、`dmidecode` 等，含 SEL 清零防漏报、10 秒超时保护、异常跳过不崩溃。

### 4.2 三层降级日志解析

| 层级 | 策略 | 适用场景 | 准确率 |
|------|------|----------|--------|
| 第一层 | 通用正则 | dmesg/mcelog 内核标准格式 | ≥95% |
| 第二层 | 关键词兜底 | 厂商差异 BMC SEL | ≥85% |
| 第三层 | LLM 语义理解 | 完全陌生私有格式 | 70~80% |

从原始日志提取 7 个核心字段：`fault_type / component / location / error_code / error_description / severity / vendor`。三层逐级降级、无缝衔接，对未知格式具备「不断线」解析韧性。

### 4.3 9 大类硬件三级阈值定级

建立覆盖 CPU、内存、存储、电源、散热、网络、PCIe、主板、BMC 共 9 大类 20 余项指标的**正常（绿）/预警（黄）/严重（红）**三级阈值模型。硬件不可纠正错误（UE）优先级最高直接定级严重；传感器数值按三级阈值判定；冗余/链路/自检等离散状态按状态字直接映射，并联动生成处置建议（如「L3 UE → 更换 CPU」「12V 偏移>10% → 更换电源模块」）。

### 4.4 RAG 知识库

自主构建 8 大类硬件故障知识库（CPU MCE、内存 ECC、传感器告警、电源、硬盘、PCIe、网卡、通用参考），内容源自 Intel SDM、JEDEC、IPMI v2.0、S.M.A.R.T、PCI-SIG 等权威规范与一线实战经验。采用向量+关键词混合检索（Top-3，Score≥0.5），以「错误码+部件+错误描述」构造查询，为大模型提供精确知识锚点。

### 4.5 AI 诊断推理

Dify 工作流 LLM 节点以 `Temperature=0.1` 推理，输出**四段式 Markdown 报告**（故障现象定位 / 物理根因推导 / 工程处置建议 / 置信度评估），SSE 流式吐出，前端打字机渲染。

### 4.6 三重防幻觉后处理（核心创新）

Prompt 仅是软约束。中转层在完整流式报告接收完毕后执行 `validate_and_fix_report()`：四段标题完整性校验（缺失自动补全）、溯源标注检测（未标注强制警示）、知识库无匹配强制替换兜底报告。详见 [知识库与防幻觉机制](知识库与防幻觉机制.md)。

### 4.7 前端展示

React + Tailwind 双栏布局：左栏黑底绿字终端输入框（日志 + 脱敏开关），右栏 Markdown 流式渲染面板。故障插槽编号前端自动红色加粗放大 3 倍；支持中英切换、一键复制、TXT 导出、诊断归档。

### 4.8 扩展性设计

MVP 底层架构无耦合，预留扩展接口：指标自定义、厂商专属 Parser、Ansible/SNMP 采集模式，均可在不重构核心链路的前提下升级至二期完整版。

## 5. 采集层（Agent）

- 语言：Python 3.6+，无重型依赖
- 托管：systemd 开机自启、异常自动重启
- 周期：5 分钟轮询；容错：10 秒命令超时、BMC 连接异常不崩溃
- 增量：本地游标 + SEL 清零，避免重复上报
- 安装：`curl -fsSL "http://<中心IP>:3000/api/agent/install.sh?server_id=Node-01" | sudo bash`

---

## 6. 安全与数据设计

所有日志进入 FastAPI 执行**两轮脱敏**（入库前 + 转发 AI 前）：`IPv4 → 10.0.0.X`、`设备 SN → SN_XXXXXX`、`运维账号 → operator_X`。API 密钥经环境变量注入不落地明文；接口仅向内网管理网开放。全面满足运营商数据安全合规要求。

---

## 7. 部署方案

提供**中心端一键部署**：`install-all.sh` 自动完成环境校验、Docker 引擎离线安装、核心容器镜像加载与编排、工作流与知识库导入，输出访问地址与默认账号。支持两种部署包：

- **内网离线版**：内置 Docker 引擎离线安装包 + Qwen2-7B 本地模型（显存 ≤5.5 GB），全链路零外网依赖。
- **公网版**：使用 Dify 外部 LLM API。

完整流程见 [离线部署手册](离线部署手册.md)；部署验证与测试用例见 [部署与测试报告](部署与测试报告.md)。

## 11. 技术局限与展望

1. **知识库覆盖度依赖**：全新厂商私有错误码依赖 LLM 语义兜底（70~80%），定位精度略降。→ 后续开发五套厂商专属 Parser 并扩充知识库。
2. **单条独立诊断，暂无时序分析**：尚不支持跨时间窗趋势识别与批量并发。→ 二期引入状态机与上下文注入。
3. **单机架构规模边界**：SQLite 单机满足 50 台并发；超大型数据中心需升级 PostgreSQL 集群与分布式架构。
4. **本地小模型能力边界**：7B 模型复杂根因推导深度有限；已预留在线 API 与本地模型灵活切换。
5. **配套运维体系待完善**：告警推送与 RBAC 权限二期补齐。

## 12. 科技创新点（对齐科技进步奖）

1. **三重防幻觉 AI 诊断架构（核心创新）**：参数层（T=0.1）+ 提示层（四段式强约束）+ 代码层（后处理硬拦截）。知识库无匹配场景 AI 编造拦截率 100%，报告四段完整率 100%，溯源标注覆盖率 100%。
2. **三层降级多源异构日志解析**：正则→关键词→LLM 语义逐级降级，全场景覆盖已知与未知格式。
3. **RAG 约束的插槽级精准定位**：利用硬件原生物理标识将结论提升至物理插槽级，前端红色加粗，运维直接带备件换件。
4. **9 大类硬件三级阈值自动定级模型**：标准化定级 + 规范化处置建议，消除工程师间判断差异。
5. **全离线极简私有化部署与数据安全**：一条命令、零外网依赖、日志二次脱敏、密钥不落地，满足关键信息基础设施合规。

### 与同类技术对比

| 维度 | 常规方案 | 本系统 |
|------|----------|--------|
| AI 幻觉控制 | 仅 Prompt 软约束 | 三重保障，无匹配编造拦截率 100% |
| 故障定位 | 笼统（「内存故障」） | 插槽级（「Channel 2, DIMM 3」） |
| 日志兼容 | 单一正则，厂商切换即失效 | 三层降级，覆盖已知+未知 |
| 知识库兜底 | 可能编造 | 强制「无法定位，需人工检测」 |
| 部署 | 依赖云服务/复杂配置 | 一条命令极简私有化，全离线 |
