# 服务器网卡故障诊断与处置规范

## 1. 网卡监控概述

服务器网卡（NIC, Network Interface Controller）是服务器与外部网络通信的核心硬件组件，负责处理物理层到数据链路层的数据收发。常见类型按接口分为电口（RJ45/CAT6，1G/10G为主）和光口（SFP+/QSFP28/QSFP56，10G/25G/100G/200G/400G）；按厂商分为 Intel（ixgbe/ice 驱动）、Mellanox/NVIDIA（mlx5_core 驱动）、Broadcom（bnxt_en 驱动）等。

常见故障模式包括：物理链路中断、错误包（CRC/FCS）递增、光模块老化导致光功率衰减、网卡/光模块温度过高、协商速率意外下降、固件 Bug 导致性能抖动、PCIe 链路降级导致带宽受限等。持续监控网卡关键指标并结合光模块 DDM 诊断，是实现故障早期预警、避免业务中断的有效手段。

## 2. 监控指标

| 指标名称 | 说明 | 采集方式 |
|---------|------|---------|
| 链路状态 | 网口物理链路是否 Up/Down | `ip link show <iface>` 或 `ethtool <iface>` |
| 协商速率 | 当前协商的速率和双工模式 | `ethtool <iface>` |
| 链路降级 | 当前速率是否低于硬件支持的最高速率 | 对比 `ethtool` 的 Supported link modes 和 Advertised link modes 与当前 `Speed` |
| 接收错误包 | CRC 错误、帧对齐错误、符号错误等 | `ethtool -S <iface>` 或 `/sys/class/net/<iface>/statistics/` |
| 发送错误包 | 发送失败、冲突、载波错误等 | `ethtool -S <iface>` 或 `/sys/class/net/<iface>/statistics/` |
| 丢包计数 | 接收/发送方向丢弃的数据包数 | `ip -s link show <iface>` 或 `ethtool -S <iface>` |
| 网卡温度 | 网卡芯片温度（部分网卡支持） | `ethtool -m <iface>` 或 `sensors` |
| 光模块状态 | SFP/QSFP 光模块的电压、温度、偏置电流、发射/接收功率 | `ethtool -m <iface>` |
| 光模块告警 | 光模块 DDM/DOM 的告警和警告标志位 | `ethtool -m <iface>` |
| 网卡固件状态 | 网卡固件版本，是否有已知 Bug 或需要更新 | `ethtool -i <iface>` 查看固件版本 |
| PCIe 链路状态 | 网卡作为 PCIe 设备时的链路状态和带宽 | `lspci -vvv -s <BDF>` |

## 3. 统计计数器解读

参考 Linux 内核网络驱动文档和 ethtool 手册，`ethtool -S` 输出的常见统计计数器及其含义如下：

| 计数器名称 | 含义 | 故障关联 |
|-----------|------|---------|
| rx_crc_errors | 接收 CRC 校验错误数。表示帧校验序列（FCS）不匹配 | 线缆质量问题、光模块老化信号畸变、对端设备故障、光纤端面脏污 |
| rx_frame_errors | 接收帧对齐错误（Frame Alignment Error）。帧长度非整数字节或帧定界异常 | 物理层信号问题，常见于电口线缆过长、串扰、或连接器接触不良 |
| rx_over_errors | 接收端 FIFO 溢出次数。表示网卡硬件缓冲区被填满后仍有数据到达 | 网卡接收缓冲区不足、CPU 处理速率低于入向流量、中断合并（Interrupt Coalescing）配置不当 |
| rx_missed_errors | 接收端漏包次数。FIFO 满后新数据被直接丢弃的累积计数 | PCIe 带宽不足或 DMA 延迟过高导致网卡无法及时将数据写入主机内存 |
| rx_length_errors | 帧长度错误。帧长超过 MTU 或小于最小帧长（Runt Frame） | MTU 不匹配（如巨型帧配置不一致）、对端驱动异常 |
| rx_fifo_errors | 接收 FIFO 错误。与 rx_over_errors 类似但代表更底层的硬件队列溢出 | PCIe 带宽瓶颈、DMA 引擎配置不当 |
| rx_errors | 接收错误总数。汇总指标 | 非零即应排查，需要结合子计数器定位具体原因 |
| tx_errors | 发送错误总数。汇总指标 | 需结合子计数器判断原因，可能是硬件、总线或介质问题 |
| tx_aborted_errors | 发送中止次数。网卡尝试发送但被中止的次数 | 网卡硬件故障、总线冲突、或 DMA 操作失败 |
| tx_carrier_errors | 载波检测错误。网卡在发送时检测不到载波信号 | 物理介质断开或严重退化、线缆未插紧 |
| tx_fifo_errors | 发送端 FIFO 错误 | 网卡发送缓冲区异常、或 PCIe 总线写入被阻塞 |
| tx_heartbeat_errors | 心跳信号错误。仅在半双工模式下有意义 | 物理层问题，全双工模式下此计数器无意义 |
| tx_window_errors | 发送窗口错误。仅在早期以太网协议中出现 | 现代服务器环境通常不会触发 |
| collisions | 冲突次数 | 仅半双工模式下有意义；全双工模式下此计数器应为 0，若出现非零值说明双工模式不匹配 |
| rx_pause / tx_pause | 流控暂停帧（PAUSE frame）计数 | 正常有少量说明对端偶尔拥塞；若频繁快速增长说明对端处理压力大或网络拥塞持续 |
| rx_dropped | 接收丢弃计数。内核网络栈因处理能力不足而丢弃的数据包 | 软中断（softirq）处理不及时、socket buffer 不足、应用层消费过慢 |
| tx_dropped | 发送丢弃计数。发送队列满导致丢弃 | 网卡发送队列（tx queue）深度不足、网卡发送速率低于应用发包速率 |
| fcs_errors | FCS 校验错误数。功能等同于 rx_crc_errors，不同厂商命名差异 | 线缆或光模块问题，该计数器非零应立即排查物理介质 |
| rx_mac_errors | MAC 层错误计数（Intel 网卡特有） | 收到无效帧的总计数，结合 rx_crc_errors 和 rx_frame_errors 综合判断 |

> **厂商差异说明**：不同厂商的网卡驱动使用不同的命名约定：
> - **Intel**（ixgbe/ice/i40e）：`rx_crc_errors`、`rx_missed_errors`、`tx_aborted_errors`、`rx_mac_errors`
> - **Mellanox/NVIDIA**（mlx5_core/mlx4）：`rx_prio0_crc_errors`、`rx_prio0_frame_errors`（带优先级前缀 0-7）、`tx_discards_phy`、`rx_discards_phy`
> - **Broadcom**（bnxt_en）：`rx_err_crc`、`rx_err_frame`、`tx_err_*` 系列

建议在采集日志时建立统一的映射规则，将不同厂商的计数器名称映射为通用字段名（如 `crc_errors`、`frame_errors`），便于跨厂商统一判定。

## 4. 光模块诊断（DDM/DOM）判定标准

参考 SFF-8472 标准，光模块数字诊断监控（DDM）的关键指标和判定阈值如下：

| 指标 | 正常范围 | 预警阈值 | 严重阈值 |
|------|---------|---------|---------|
| 温度 | <45°C | 45–55°C | >55°C |
| 电压 | 3.135–3.465V | 3.1–3.135V 或 3.465–3.5V | <3.1V 或 >3.5V |
| 偏置电流 (TX Bias) | 高于告警低阈值 20% | 接近告警低阈值 20% 以内 | 低于告警低阈值 |
| 发射功率 (TX Power) | 出厂范围 ±3dB | 偏离出厂范围 3–6dB | 偏离出厂范围 >6dB |
| 接收功率 (RX Power) | 高于接收灵敏度 3dB 以上 | 接近接收灵敏度 3dB 以内 | 低于接收灵敏度 |

### 阈值说明

- SFF-8472 标准定义了光模块内置的 High Alarm / Low Alarm / High Warning / Low Warning 四个阈值。`ethtool -m` 输出的 "Alarm flags" 和 "Warning flags" 直接反映这些阈值是否被突破。
- **告警标志（Alarm Flag）**：任意告警标志置位时 → 🔴 严重。意味着参数已超出厂商安全运行范围，光模块即将或已失效。
- **警告标志（Warning Flag）**：任意警告标志置位但无告警时 → 🟡 预警。意味着参数正在偏离正常范围，需关注趋势。
- **接收功率特别说明**：接收功率是最关键的指标之一。光模块老化首先表现为接收功率下降，当接收功率接近接收灵敏度时（即低于灵敏度不超过 3dB），链路 BER（误码率）将急剧上升，表现为 CRC 错误增长。应及时更换衰减模组。

```
# 光模块告警日志示例
kernel: ixgbe 0000:17:00.0 eth0: Optics SFP ALARM: TX power low
kernel: ixgbe 0000:17:00.0 eth0: Optics SFP WARNING: RX power low
```

## 5. 判定标准

### 5.1 链路状态判定

| 等级 | 判定条件 |
|:----:|----------|
| 🟢 正常 | 链路 Up，协商速率为硬件支持的最高速率 |
| 🟡 预警 | 链路 Up，但协商速率低于硬件最高速率（链路降级）；或链路在 1 小时内出现 ≥3 次 Up/Down 切换 |
| 🔴 严重 | 链路持续 Down；或链路速率降至最低协商速率（如 100Mbps 甚至 10Mbps，而网卡支持 10Gbps+） |

### 5.2 错误包判定

| 等级 | 判定条件 |
|:----:|----------|
| 🟢 正常 | 所有错误计数器为 0，或偶发非零但无递增趋势 |
| 🟡 预警 | 错误包存在递增趋势，但错误速率低于总流量的 0.1%；或连续两个采样周期错误计数递增 |
| 🔴 严重 | 错误包持续增长且超过总流量的 1%；或 CRC/FCS 错误短时间内高频出现（>100/min）；或 rx_over_errors / rx_missed_errors 快速增长 |

### 5.3 光模块判定

| 等级 | 判定条件 |
|:----:|----------|
| 🟢 正常 | 所有 DDM 指标在正常范围，无告警标志也无警告标志 |
| 🟡 预警 | 任意警告标志（Warning Flag）置位；或接收功率接近灵敏度极限（灵敏度 +3dB 以内）；或温度/电压接近预警阈值 |
| 🔴 严重 | 任意告警标志（Alarm Flag）置位；或接收功率低于灵敏度；或发射功率异常偏离出厂值 >6dB；或偏置电流低于告警低阈值 |

### 5.4 网卡/光模块温度判定

| 等级 | 判定条件 |
|:----:|----------|
| 🟢 正常 | <65°C |
| 🟡 预警 | 65–80°C |
| 🔴 严重 | >80°C |

### 5.5 丢包判定

| 等级 | 判定条件 |
|:----:|----------|
| 🟢 正常 | 丢包率 0% |
| 🟡 预警 | 丢包率 0.01%–0.1% |
| 🔴 严重 | 丢包率 >0.1% |

> 丢包率 = `(tx_dropped + rx_dropped) / (总包数)`。在实际运维中，任何非零的持续丢包都应引起关注。`ifconfig` 或 `ip -s link show` 输出的 dropped 计数可用于快速判断。

### 5.6 综合判定矩阵

| 场景 | 判定 |
|------|:----:|
| 链路 Up + CRC Error = 0 + 光模块正常 | 🟢 正常 |
| 链路 Up + CRC Error > 0 但 < 0.1% + 光模块 Warning | 🟡 预警 |
| 链路 Up + CRC Error > 0.1% + 光模块 Warning | 🟡 预警（升级观察） |
| 链路 Down 且重插无效 | 🔴 严重 |
| 链路 Up（降级） + CRC Error > 1% + 光模块 Alarm | 🔴 严重 |
| 任何 Fatal PCIe AER Error（如 Completion Timeout） | 🔴 严重 |

## 6. 处置建议

### 6.1 预警等级处置

| 故障场景 | 处置步骤 |
|----------|----------|
| 链路降级 | ① 检查网线/光模块是否松动，重新插拔；② 检查对端交换机端口配置（速率/双工/流控）；③ `ethtool -S` 检查错误包是否增长；④ 若降级持续，更换线缆或光模块交叉测试 |
| 错误包递增 | ① 更换网线或光模块测试，对比错误是否消失；② 清洁光纤端面（使用专用光纤清洁工具）；③ 检查线缆长度是否超过标准（Cat6 ≤ 55m 用于 10G，Cat6a ≤ 100m）；④ 检查对端交换机端口错误计数 |
| 光模块警告 | ① 记录当前光功率、温度、偏置电流值，建立观测基线；② 每日定时采集 `ethtool -m` 输出，追踪光功率衰减趋势；③ 准备同规格备件（SFP+/QSFP28 等），在下一个维护窗口更换 |
| 温度预警 | ① 检查机箱通风和风扇转速，确认进风口无阻塞；② 检查网卡散热片是否积尘；③ 若同机箱其他设备温度正常而仅网卡偏高，可能是网卡自身散热问题 |
| 低丢包 | ① 检查中断合并（Interrupt Coalescing）参数，`ethtool -c <iface>` 查看 rx-usecs 和 tx-usecs；② 检查 Ring Buffer 大小，`ethtool -g <iface>`；③ 若仅收包丢弃，检查 CPU 亲和性和 IRQ 均衡（`/proc/interrupts`） |

### 6.2 严重等级处置

| 故障场景 | 处置步骤 |
|----------|----------|
| 链路 Down | ① 重新插拔线缆和光模块；② `ethtool <iface>` 确认 `Link detected: no`；③ 检查对端交换机端口状态和日志；④ 更换线缆→更换光模块→更换网卡，逐步隔离根因 |
| 错误包高频 | ① 立即更换光模块或线缆，测试更换后错误是否消失；② 若更换介质后错误仍存在，排查对端交换机端口；③ 排除介质和交换机后仍有错误，可能是网卡本身硬件故障 |
| 光模块告警 | ① 立即更换光模块；② 检查光纤链路端面清洁度（使用光纤显微镜），必要时清洁或更换光纤跳线；③ 确认更换后所有告警标志清除 |
| 温度严重 | ① 立即检查机箱散热（风扇转速、风道、机房环境温度）；② 若为被动散热网卡在高温机箱内运行，考虑加装独立风扇或更换为主动散热型号；③ 高温可能导致永久性硬件损伤，恢复后也应观察是否有新增的错误计数器增长 |
| 持续高丢包 | ① 将受影响服务器从生产流量中摘除（如从负载均衡 upstream 池中移除）；② 检查丢包是否由软件层导致（softirq CPU 使用率、socket buffer、iptables/nftables 规则）；③ 排除软件原因后，按错误包高频流程排查硬件 |
| PCIe AER Fatal | ① 参考《服务器 PCIe 错误类型与排障指南》；② Completion Timeout 或 Malformed TLP 出现时，优先怀疑 PCIe 链路物理问题；③ 更换网卡所在插槽或 Riser 卡交叉测试；④ 若问题跟随网卡迁移，判定为网卡硬件故障 |

### 6.3 软件层疑难问题排查

| 问题 | 排查命令 | 说明 |
|------|---------|------|
| Ring Buffer 不足 | `ethtool -g <iface>` | 检查当前值和最大值，适当调大 `ethtool -G <iface> rx 4096` |
| 中断合并参数不当 | `ethtool -c <iface>` | rx-usecs 过大会导致延迟，过小会导致 CPU 开销增大；低延迟场景建议 8-20µs，高吞吐场景建议 50-100µs |
| IRQ 不均衡 | `cat /proc/interrupts \| grep <iface>` | 确保网卡中断分散到多个 CPU 核（需启用 irqbalance 或手动设置 smp_affinity） |
| 内核丢包 | `netstat -s \| grep -i drop` | 查看内核协议栈各层的丢包统计，判断是 TCP/UDP 层还是网卡层丢弃 |
| 流控配置 | `ethtool -a <iface>` | 确认 PAUSE 帧设置与对端交换机一致；若交换机不支持 PFC 而服务器开启，可能导致链路异常 |

## 7. Linux 日志识别

### 7.1 dmesg 典型日志格式

```text
# 网卡链路状态变化
kernel: ixgbe 0000:17:00.0 eth0: NIC Link is Down
kernel: ixgbe 0000:17:00.0 eth0: NIC Link is Up 10 Gbps Full Duplex, Flow Control: RX/TX

# 网卡硬件错误（Mellanox）
kernel: mlx5_core 0000:17:00.0: health critical: Internal error detected

# 网卡硬件错误（Intel）
kernel: ixgbe 0000:17:00.0: Hardware Error

# 网卡固件异常
kernel: bnxt_en 0000:17:00.0 eth0: Firmware fatal error, resetting

# 光模块告警/警告
kernel: ixgbe 0000:17:00.0 eth0: Optics SFP ALARM: TX power low
kernel: ixgbe 0000:17:00.0 eth0: Optics SFP WARNING: RX power low
kernel: ixgbe 0000:17:00.0 eth0: Optics SFP ALARM: Temperature high

# PCIe AER 错误（网卡相关）
kernel: pcieport 0000:00:1c.0: AER: Corrected error received: id=00e0
kernel: pcieport 0000:00:1c.0: AER: Uncorrected (Fatal) error received: id=00e0
```

### 7.2 日志字段解析

| 字段 | 说明 | 示例 |
|------|------|------|
| `0000:17:00.0` | 网卡的 PCIe BDF 地址 | `0000:17:00.0` |

## 8. 常用诊断命令

```bash
# 查看网口状态和统计
ip -s link show <iface>
ethtool <iface>
ethtool -S <iface>

# 查看光模块完整 DDM 信息
ethtool -m <iface>

# 查看网卡固件和驱动信息
ethtool -i <iface>

# 查看网卡 PCIe 设备地址和链路状态
lspci -vvv -s <BDF> | grep -E "LnkSta:|LnkCap:"

# 查看 Ring Buffer 和中断合并参数
ethtool -g <iface>
ethtool -c <iface>

# 查看流控（PAUSE 帧）配置
ethtool -a <iface>

# 持续监控网卡错误增量（每秒刷新）
watch -n 1 "ethtool -S <iface> | grep -E 'rx_crc|rx_errors|tx_errors|rx_dropped|tx_dropped'"

# 抓取指定网口的实时流量和错误（需要安装 ifstat）
ifstat -i <iface> -t 1

# 查看中断和 IRQ 均衡
cat /proc/interrupts | grep <iface>

# 查看内核协议栈丢包统计
netstat -s | grep -i drop

# 查看所有网口的光模块告警（批量）
for iface in $(ls /sys/class/net/); do
    if ethtool -m $iface 2>/dev/null | grep -qi "alarm"; then
        echo "=== $iface ==="
        ethtool -m $iface | grep -E "Alarm|Warning"
    fi
done

# 查看网卡链路降级情况（对比能力和当前状态）
ethtool <iface> | grep -A 20 "Supported link modes"
```
