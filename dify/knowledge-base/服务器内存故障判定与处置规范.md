# 服务器内存（DRAM）故障判定与处置规范

## 1. 内存故障概述

服务器内存（DDR4/DDR5 DRAM）是 CPU 与存储系统之间的核心数据缓存层，所有运行中的程序和数据均加载于内存中。服务器内存普遍采用 ECC（Error Correction Code）技术，通过额外的校验位（DDR4 每 64-bit 数据附加 8-bit ECC，DDR5 每 32-bit 子通道附加独立 ECC）实现单比特错误自动纠正（CE, Correctable Error）和多比特错误检测（UE, Uncorrectable Error）。

常见故障模式包括：单粒子翻转（SEU，高能粒子击中 DRAM 存储单元导致瞬态比特翻转）、Row Hammer 效应（频繁激活相邻行导致目标行电容漏电）、介质老化（Dielectric Degradation，DRAM 电容氧化层随时间退化导致数据保持时间缩短）、金手指氧化/接触不良（DIMM 金手指与插槽触点间电阻增大）、DIMM 插槽故障（插槽内部引脚弯曲、焊点开裂、或灰尘积聚导致接触不良）。

## 2. 监控指标

| 指标名称 | 说明 | 采集方式 |
|---------|------|---------|
| CE 计数 | Correctable Error 发生次数（每个 Bank/Channel 独立累计） | `mcelog` 或 `dmesg` 中的 `Corrected error` 记录 |
| UE 计数 | Uncorrectable Error 发生次数 | `mcelog` 或 `dmesg` 中的 `Uncorrected error` 记录 |
| CE 发生位置 | CE 发生的物理地址（Channel/DIMM/Rank/Bank/Row/Col） | `mcelog` 输出中的 Memory 段、EDAC `sysfs` 下的 `ce_count` |
| CE 发生频率 | 单位时间（1小时）内同一地址位置的 CE 次数 | Agent 采集后由中心端统计分析 |
| 内存温度 | DIMM 温度传感器读数（来自 SPD 温度传感器或 BMC） | `ipmitool sdr type Temperature` 或 `sensors` |
| 内存页错误 | 操作系统检测到并向内核报告的内存页错误（MCE 或 EDAC 触发） | `dmesg` 中的 `Memory failure`、`HWPOISON`、`Uncorrected` |
| DIMM 在位状态 | DIMM 是否被 BIOS/OS 识别，是否存在 SPD 读取故障 | `dmidecode -t memory` 或 `lshw -class memory` |
| DIMM 配置信息 | DIMM 型号、容量、速率、Rank 数、厂商 | `dmidecode -t memory` |

> **注意**：部分老平台仅支持 MCE（Machine Check Exception）方式上报，较新平台支持 EDAC（Error Detection and Correction）驱动以更结构化的方式上报。`dmesg` 日志中 CE 以 `EDAC MC` 或 `MCE: Corrected` 开头，UE 以 `Hardware memory error` 或 `MCE: Uncorrected` 开头。

## 3. 判定标准

### 3.1 CE（可纠正错误）判定

| 等级 | 图标 | 判定条件 |
|:----:|:----:|----------|
| 正常 | 🟢 | 无 CE 记录 |
| 预警 | 🟡 | 单次 CE，且地址分散（不在同一 Row/Col），24 小时内无再次出现 |
| 警告 | 🟠 | 同一 Row/Col 在 1 小时内出现 ≥3 次 CE；或 CE 计数呈线性递增趋势（连续 3 个采样周期递增）；或大量 CE 集中在同一物理区域（同一 Channel 或同一 DIMM）；或同一 DIMM 累计 CE 超过 100 次 |

### 3.2 UE（不可纠正错误）判定

| 等级 | 图标 | 判定条件 |
|:----:|:----:|----------|
| 严重 | 🔴 | 出现任何 UE（Uncorrectable hardware error）。无论发生频率如何，UE 即视为硬件故障 |

### 3.3 内存温度异常判定

| 等级 | 图标 | 判定条件 |
|:----:|:----:|----------|
| 正常 | 🟢 | <85°C |
| 预警 | 🟡 | 85–95°C |
| 严重 | 🔴 | ≥95°C |

### 3.4 CE 判定流程图（文字描述）

```
日志中出现 ECC 错误
│
├── UE → 🔴 严重：立即隔离服务器，指出 DIMM 物理位置，更换内存条
│
└── CE
    ├── 单次偶发、地址分散、24小时内无再现 → 🟡 预警：记录位置和地址，观察 24 小时
    ├── 同一 Row/Col 在 1 小时内 ≥3 次 CE、或呈线性递增趋势 → 🟠 警告：判定为介质老化或 Row Hammer，排期更换
    ├── CE 伴随高温（≥85°C）→ 🟡 预警+ ：优先改善散热后再观察 CE 趋势
    └── CE 集中在同一 DIMM 且累计 >100 次 → 🟠 警告：高概率介质故障，排期更换
```

## 4. 处置建议

### 4.1 预警等级（🟡 偶发 CE）

| 步骤 | 操作 |
|:----:|------|
| 1 | 记录 CE 发生的时间戳、物理位置（Channel/DIMM/Rank/Bank/Row/Col）和 MCi_STATUS 寄存器值 |
| 2 | 设 24 小时观察窗口。若窗口内不再出现 CE，判定为单粒子翻转（SEU），无需更换硬件 |
| 3 | 若观察窗口内再次出现 CE 或频率增加，升级为 🟠 警告等级处理 |
| 4 | 记录事件到维护日志，标记该 DIMM 为"观察中"状态 |
| 5 | 检查内存工作温度。若温度 ≥85°C，按 4.4 温度异常处置执行 |

### 4.2 警告等级（🟠 高频/集中 CE）

| 步骤 | 操作 |
|:----:|------|
| 1 | 判定可能根因：Row Hammer 效应（集中在同一 Row）、介质老化（CE 递增趋势）、金手指氧化（重新插拔后消失） |
| 2 | 准备同型号、同频率 DIMM 备件（通过 `dmidecode -t memory` 获取 Part Number 和 Speed 对号采购） |
| 3 | 在下一个计划维护窗口内更换故障 DIMM（精确指定物理位置，如 Channel 2, DIMM 3） |
| 4 | 若判定为 Row Hammer 效应，临时缓解措施：进入 BIOS/UEFI 提高 DRAM Refresh Rate（缩短 tREFI 参数），或采用 pTRR（Pseudo Target Row Refresh）机制（若平台支持） |
| 5 | 若怀疑金手指氧化，先尝试关机 → 拔出 DIMM → 使用橡皮擦轻擦金手指 → 重新安装，观察 CE 是否消失。若消失则继续使用并定期复查 |
| 6 | 更换操作后，运行 memtest86+ 至少 1 个完整 Pass（约 1-4 小时，取决于内存容量），确认无新增 CE/UE |
| 7 | 对更换下来的旧 DIMM 贴标签、记录序列号和错误历史，交返厂商 RMA 分析或报废 |

### 4.3 严重等级（🔴 UE）

| 步骤 | 操作 |
|:----:|------|
| 1 | 立即通告运维和业务团队，启动应急响应。一个 UE 意味着已有不可恢复的数据错误，存在数据损坏风险 |
| 2 | 立即将该服务器从生产集群摘除（如从负载均衡 upstream 池中移除、K8s cordon+drain、或切业务至备机） |
| 3 | 从日志中精准提取故障 DIMM 的物理位置：Channel X, DIMM Y（从 `mcelog` Memory 段或 EDAC 日志获取） |
| 4 | 携带同型号备件前往机房/使用远程操作，更换指定插槽上的内存条 |
| 5 | 更换后运行 memtest86+ 或 `stress-ng --vm N --vm-bytes X` 进行至少 4 小时内存压力测试，覆盖全地址空间 |
| 6 | 压力测试通过后，将服务器重新加入生产集群，持续监控 72 小时无新增 CE/UE 方可标记为恢复 |
| 7 | 若 UE 伴随 `Processor context corrupted`（MCi_STATUS 的 PCC 位置位），说明 CPU 上下文已被破坏，除更换内存外还需排查 CPU 是否有残留影响，建议重启后观察 |

### 4.4 温度异常处置

| 步骤 | 操作 |
|:----:|------|
| 1 | 检查服务器进风口温度（机房环境温度应 ≤25°C） |
| 2 | 检查 DIMM 区域的通风：确保 DIMM 间隙无积尘阻挡气流，风扇模块（FAN Module）转速正常 |
| 3 | 检查 DIMM 是否正确安装于交错散热槽位（部分服务器要求 DIMM 按特定顺序安装以确保散热均匀） |
| 4 | 高温（≥85°C）会加速 DRAM 电容漏电和氧化层退化，即使当前无 CE 也应在 7 天内改善散热。持续在 95°C 以上运行会永久性降低 DIMM 寿命 |
| 5 | 若散热改善后温度仍持续偏高，该 DIMM 可能存在内部短路或异常功耗，应在下一个维护窗口更换 |

## 5. 根因分析指南

| 错误模式 | 可能物理根因 | 判断依据 |
|---------|-------------|---------|
| 单次 CE，地址随机，不重复 | 单粒子翻转（SEU） | 高能粒子撞击 DRAM 存储单元，随机且不重复；海拔越高、太阳活动越强，SEU 率越高 |
| CE 集中在同一 Row | Row Hammer 效应 | 相邻行频繁激活导致目标行电容漏电；可通过提高刷新率（缩短 tREFI）临时缓解 |
| CE 集中在同一 Col | Column 译码器故障 | 同一列地址线短路或开路；更换 DIMM 后问题消失 |
| CE 集中在同一 Bank 但多 Row/Col | Bank 级电路故障 | Sense Amplifier 或 Bank 控制逻辑缺陷 |
| CE 计数随时间递增 | 介质老化（Dielectric Degradation） | DRAM 电容氧化层退化导致保持时间缩短，CE 率随时间单调增加 |
| CE 与物理扰动相关（重新插拔后消失） | 金手指氧化/接触不良 | DIMM 金手指与插槽触点间接触电阻增大；橡皮擦清洁或重新插拔后 CE 消失 |
| CE 伴随高温 | 温度加速老化 | 高温下 DRAM 漏电增加，数据保持时间缩短；温度每升高 10°C，DRAM 漏电流约翻倍 |
| UE 突发，之前无 CE | 单一 Cell 完全失效 | 电容击穿、晶体管失效或位线短路；属于硬故障，必须立即更换 |
| UE 在 CE 递增后出现 | 渐进式退化至硬故障 | 介质老化从 CE 发展为 UE，说明退化已跨过 ECC 纠错能力的临界点 |
| 同一 Channel 多个 DIMM 同时报 CE | Channel 级故障 | 内存控制器故障、主板走线信号完整性问题或时钟/地址线异常 |
| CE 在更换 DIMM 到另一槽位后跟随迁移 | DIMM 自身故障 | 故障随 DIMM 迁移，排除插槽问题 |
| CE 在更换 DIMM 但 CE 仍留在原槽位 | 插槽故障 | 故障不随 DIMM 迁移，排除 DIMM 问题 |

## 7. 日志字段映射（适配本系统解析模块）

### 7.1 映射规则

从日志中提取关键字段，按以下规则映射到系统的结构化数据：

| 日志字段 | 系统提取字段 | 提取规则 | 示例值 |
|---------|------------|---------|--------|
| MCE / EDAC 类型标识 | `fault_type` | 固定值 `Memory` | `Memory` |
| MCE / EDAC 组件分类 | `component` | 固定值 `Memory` | `Memory` |
| Memory: channel X, DIMM Y | `location` | 从 `mcelog` Memory 段或 EDAC `Chan_X_DIMM_Y` 中提取 | `Channel 2, DIMM 3` |
| row X, col Y | `location_detail` | 从 `mcelog` Memory 段提取 Row 和 Col 值 | `row 12345, col 678` |
| Error code 0xNNNN 或 EDAC 错误类型 | `error_code` | 从 `MCi_STATUS` 寄存器的 MCA Error Code（Bits 0-15）提取；若为 EDAC 则记录 CE/UE 类型 | `0x0005` / `CE` / `UE` |
| Corrected error / Uncorrected error | `error_description` | 从日志中提取错误描述原文 | `Corrected ECC error` / `Uncorrected ECC error` |
| Corrected error → Warning、Uncorrected error → Critical | `severity` | CE → `Warning`；UE → `Critical`（注意：UE 为 Critical 等级，在 UI 显示为 🔴 严重） | `Warning` / `Critical` |
| CPU X BANK Y | `source` | 从 `mcelog` 的 CPU/BANK 段提取 | `CPU 0 Bank 4` |
| 根据日志特征或 dmidecode 结果 | `vendor` | 按 DIMM 制造商信息（如 Samsung/SK Hynix/Micron）或服务器厂商特征（如 Dell/HPE/Lenovo/Inspur/Huawei）提取；无法识别时填 `Generic` | `Samsung` / `Dell` / `Generic` |

### 7.2 厂商识别方法

| 识别来源 | 方法 | 示例 |
|---------|------|------|
| `dmidecode -t memory` | `Manufacturer` 字段为 DIMM 颗粒厂商 | `Samsung`、`SK Hynix`、`Micron` |
| `dmidecode -t system` | `Manufacturer` 字段为服务器整机厂商 | `Dell Inc.`、`HPE`、`Lenovo` |
| EDAC label | 部分厂商在 EDAC label 中内嵌厂商标识 | `CPU_SrcID#0`（Intel）、`Dell R740` |
| IPMI FRU | `ipmitool fru print` 查看 Board Mfg（服务器主板厂商） | `Dell`、`Inspur`、`Huawei` |

## 8. 常用诊断命令

```bash
# 查看所有内存错误日志
mcelog --client

# 查看 EDAC 内存错误计数
cat /sys/devices/system/edac/mc/mc*/ce_count
cat /sys/devices/system/edac/mc/mc*/ue_count

# 查看 DIMM 详细信息
dmidecode -t memory

# 查看内存温度（BMC）
ipmitool sdr type Temperature | grep -i mem

# 查看内存温度（OS 级 lm-sensors）
sensors | grep -i dimm

# 查看 MCE 日志（若 mcelog 未安装）
ras-mc-ctl --summary
ras-mc-ctl --errors

# 查看内核内存错误日志
dmesg | grep -iE "mce|edac|hardware error|memory failure|h/w poison"

# 运行内存压力测试（更换后验证，至少 4 小时）
memtest86+      # 需重启，从引导介质启动
stress-ng --vm 8 --vm-bytes 80% --timeout 4h   # 在线测试，需预留足够空闲内存

# 查看内存拓扑（Channel/DIMM 编号映射）
lstopo --of console | grep -A 2 Memory
```
