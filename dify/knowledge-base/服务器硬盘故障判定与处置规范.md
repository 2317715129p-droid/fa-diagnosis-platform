# 服务器硬盘故障判定与处置规范

## 1. 硬盘监控概述

### 1.1 服务器硬盘常见类型

| 类型 | 存储介质 | 典型容量 | 典型寿命（MTBF） | 使用场景 |
|------|----------|----------|-----------------|----------|
| HDD（机械硬盘） | 磁性盘片 + 机械磁头 | 2TB – 24TB | 100–250 万小时 | 冷数据存储、大容量归档、备份 |
| SSD（固态硬盘） | NAND Flash | 480GB – 30TB | 150–250 万小时 | 热数据、数据库、高频读写 |

### 1.2 S.M.A.R.T. 技术简介

S.M.A.R.T.（Self-Monitoring, Analysis and Reporting Technology）是内置于现代硬盘固件中的自我监测系统。它持续跟踪数十项与可靠性和性能相关的属性（Attribute），通过原始值（Raw Value）和归一化值（Normalized Value）反映硬盘健康状况。当某项属性超过厂商设定的阈值（Threshold），硬盘会被判定为 S.M.A.R.T. FAILED 状态，表示故障风险急剧升高。

### 1.3 常见硬盘故障模式

| 故障模式 | 适用类型 | 典型表现 | 关联 SMART 属性 |
|----------|----------|----------|-----------------|
| 坏道（Bad Sector） | HDD | 读取特定扇区时 I/O 错误或延迟剧增 | 5, 197, 198 |
| 磁头故障（Head Crash） | HDD | 反复出现读写错误，伴随异常噪音 | 1, 7 |
| 介质磨损（Media Wear） | HDD/SSD | 随时间累积的扇区重映射增多 | 5（HDD）, 171/177/231（SSD） |
| 电路板故障 | HDD/SSD | 硬盘无法识别、随机掉电、命令超时 | 188, 199 |
| 固件故障 | HDD/SSD | 状态异常、属性突变 | 多属性指标 |
| NAND 磨损 | SSD | 剩余寿命缩短、写入性能下降 | 171, 177, 202, 231 |
| 电源/散热问题 | HDD/SSD | 高温持续运行，SMART 温度属性飙升 | 194 |

## 2. 关键 SMART 属性解读

### 2.1 通用关键属性（HDD + SSD）

| SMART ID | 属性名 | 含义 | 正常值 | 预警阈值 | 严重阈值 |
|:--------:|--------|------|:------:|:--------:|:--------:|
| 5 | Reallocated Sectors Count | 已重映射的坏扇区数量。硬盘发现坏扇区后，用备用扇区替换，该值随之增加 | 0 | 1–10 | >10 |
| 7 | Seek Error Rate | 寻道错误率（仅 HDD 有效）。机械磁头定位失败的比例 | 接近 0 | 递增趋势 | 持续增长 |
| 187 | Reported Uncorrectable Errors | 硬件层面无法纠错、报告给主机的错误次数 | 0 | 1–3 | >3 |
| 188 | Command Timeout | 命令执行超时次数。通常由盘片响应缓慢或电路异常引起 | 0 | 1–5 | >5 |
| 194 | Temperature | 硬盘当前温度（摄氏度）。Raw Value 即实际温度 | <50°C | 50–60°C | >60°C |
| 197 | Current Pending Sector Count | 候选待重映射扇区数。读写出错但尚未成功重映射的扇区 | 0 | 1–5 | >5 |
| 198 | Uncorrectable Sector Count | 离线扫描时发现的不可纠正扇区数 | 0 | ≥1 | 持续增长 |

> **重要说明**：Google 2007 年《Failure Trends in a Large Disk Drive Population》研究发现，SMART 5、187、197、198 四项属性与硬盘故障的相关性最高。Backblaze 多年运营数据进一步确认，上述四项 + SMART 188 是最值得监控的五项核心属性。任何一项出现非零值即应纳入密切关注。

### 2.2 SSD 专属关键属性

| SMART ID | 属性名 | 含义 | 正常值 | 预警阈值 | 严重阈值 |
|:--------:|--------|------|:------:|:--------:|:--------:|
| 171 | Program Fail Count / SSD Wear Level (某些厂商) | NAND 编程失败计数，或 SSD 磨损度百分比 | 0 / 100（视厂商） | 递增趋势 | 持续增长 |
| 173 | SSD Wear Leveling (各厂商) | 最大擦除次数。反映 NAND 块磨损均匀度 | 各厂商不同 | 接近额定寿命 80% | 接近额定寿命 95% |
| 174 | Unexpected Power Loss Count | 异常断电次数。频繁异常断电可能导致数据损坏 | 0 | >10 | >50 |
| 177 | Wear-Range Delta | 磨损差异百分比。反映磨损均衡效果 | <5% | 5–15% | >15% |
| 202 | Percentage of Lifetime Used | 按 TBW 计算的生命周期已使用百分比。0 为全新，100 为耗尽 | <50% | 50–80% | >80% |
| 231 | SSD Life Left (Seagate/SM 主控) / Wear Leveling Count | 剩余寿命百分比。100 为全新，0 为只读锁定 | >80% | 50–80% | <50% |

> **注意**：SSD SMART 属性号因厂商/主控不同而差异较大。常见的剩余寿命属性号包括 169（WD）、202（Crucial/Micron）、231（Seagate/SM2246XT）、177（SandForce）。实际部署时应查询厂商手册确认对应属性 ID。

## 3. 判定标准

### 3.1 HDD 三级判定

| 等级 | 图标 | 判定条件 |
|:----:|:----:|----------|
| 正常 | 🟢 | 所有关键 SMART 属性（5/187/188/197/198/7/194）均为正常值，无递增趋势 |
| 预警 | 🟡 | 满足以下任一条件：① SMART 5 = 1–10；② SMART 197 = 1–5；③ SMART 187 ≥ 1；④ SMART 198 ≥ 1；⑤ SMART 188 = 1–5；⑥ 任意属性出现加速递增趋势（连续两次采样递增）；⑦ SMART 194 = 50–60°C |
| 严重 | 🔴 | 满足以下任一条件：① SMART 5 > 10；② SMART 197 > 5；③ SMART 187 > 3；④ SMART 188 > 5；⑤ 两个及以上预警属性同时触发；⑥ SMART 194 > 60°C；⑦ 硬盘状态显示 S.M.A.R.T. FAILED |

### 3.2 SSD 三级判定

| 等级 | 图标 | 判定条件 |
|:----:|:----:|----------|
| 正常 | 🟢 | 所有通用 + SSD 专属属性均为正常值，剩余寿命 > 80%，无递增趋势 |
| 预警 | 🟡 | 满足以下任一条件：① 剩余寿命 50–80%（如 SMART 231=50–80 或 SMART 202=50–80）；② 通用属性出现预警值（同 HDD 标准）；③ 磨损差异 > 5%；④ 异常断电次数 > 10；⑤ 剩余寿命下降速度异常加快 |
| 严重 | 🔴 | 满足以下任一条件：① 剩余寿命 < 50%（如 SMART 231<50 或 SMART 202>80）；② 通用属性触发严重标准（同 HDD）；③ 两个及以上预警属性同时触发；④ 磨损差异 > 15%；⑤ 出现不可恢复的 Program Fail / Erase Fail 计数增长 |

## 4. 处置建议

### 4.1 预警等级（🟡）

| 处 置 项 | 具体操作 |
|-----------|----------|
| 持续观察 | 将采样频率从常规周期提升至每日一次，记录趋势变化 |
| 通信通告 | 通知相关业务负责人，评估潜在影响 |
| 备份强化 | 对该硬盘所在 RAID 卷执行完整性校验；增加备份频率至每日，确保备份可恢复 |
| 准备备件 | 确认备件库存，同规格替换盘就位，提交更换工单 |
| RAID 状态检查 | 确认 RAID 重建不会触发额外风险（如 RAID 5 重建期间另一盘故障） |
| 排期更换 | 在下一个计划维护窗口内安排硬盘更换，最迟不超过 7 个自然日 |

### 4.2 严重等级（🔴）

| 处 置 项 | 具体操作 |
|-----------|----------|
| 立即通告 | 以最高优先级通知运维团队和业务负责人，启动应急响应 |
| 数据备份 | 立即启动全量数据紧急备份，备份完成后校验数据完整性 |
| 业务隔离 | 将受影响服务器从生产流量中摘除（如 HAProxy/Nginx upstream 下线、K8s cordon+drain），防止数据进一步丢失 |
| 硬盘更换 | 立即更换故障硬盘，启动 RAID 重建 |
| 重建监控 | 实时监控 RAID 重建进度和 I/O 延迟，防止重建期间二次故障 |
| 复盘分析 | 故障恢复后，导出完整 SMART 历史日志，分析故障根因，更新知识库 |
| 同期排查 | 对同批次、同型号、同服役时长的其他硬盘进行主动巡检 |

### 4.3 RAID 环境特别说明

- **RAID 0**：任何硬盘故障直接导致数据丢失，预警即视同严重，立即备份并更换。
- **RAID 1/10**：单盘故障可容忍，但必须在重建完成前确保另一镜像盘健康。
- **RAID 5**：仅容忍单盘故障，重建窗口高风险，应在预警阶段即预备更换。
- **RAID 6**：容忍双盘故障，但仍应在预警阶段排期更换。
- **重建注意事项**：大型 HDD（≥16TB）的重建时间可能长达 24–72 小时，期间所有成员盘满负荷读取，增大了同批次其他盘故障概率。

## 5. 附录：smartctl 常用命令参考

```bash
# 查看所有 SMART 信息
smartctl -a /dev/sda

# 仅查看关键健康属性（精简输出）
smartctl -A /dev/sda

# 执行短期自检
smartctl -t short /dev/sda

# 查看自检结果
smartctl -l selftest /dev/sda

# 以 JSON 格式输出（便于自动化采集）
smartctl -a -j /dev/sda

# 批量采集所有磁盘 SMART 信息
for disk in $(lsblk -ndo NAME,TYPE | grep disk | awk '{print $1}'); do
    smartctl -a -j /dev/$disk > /var/log/smart_${disk}_$(date +%Y%m%d_%H%M%S).json
done
```
